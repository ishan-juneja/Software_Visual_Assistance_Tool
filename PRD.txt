Project PRD — CaptureBench Lite

Purpose: Full-stack learning project to simulate Apple’s internal camera tools environment, focused on image-quality regression detection and developer-tool UX.

🧭 1. Problem Statement

Apple’s imaging and camera-pipeline teams constantly capture photos across devices, builds, and scenes to evaluate quality regressions (e.g., “Did Build 102 worsen noise or sharpness?”).
They need lightweight tooling to upload, analyze, and visualize image metrics over time.

You’ll build a web-based dashboard and minimal backend that mimics this workflow — letting users upload sample captures, compute simple quality metrics, compare builds, and flag regressions.

This project teaches:

Full-stack fundamentals (frontend ↔ backend ↔ database)

Data visualization and metric tracking

Regression detection logic

Developer-tool UX design

End-to-end debugging and testing mindset

🎯 2. Goals (MVP Scope)
Category	Goal
Backend	Upload & store images with metadata (device, build, scene)
	Compute simple metrics: sharpness, contrast, exposure
	Compare builds to detect regressions (drops > 5%)
	Serve JSON APIs for trend & regression endpoints
Frontend	Dashboard page with metric trend charts
	Regression table (Δ values + badges)
	Compare Scrubber view for A/B visual check
	Upload panel for new captures
Data	Seed script that generates 2 builds × 10 scenes with known −10% sharpness drift
Learning	You can explain each endpoint, SQL query, and React component you wrote
🧱 3. Non-Goals (for MVP)

No user authentication or roles

No cloud storage (local folder is fine)

No perceptual or ML metrics (SSIM/LPIPS optional stretch)

No complex permission system or fancy UI polish

Not meant for production — learning tool only

⚙️ 5. Functional Requirements
Backend ( FastAPI )
Feature	Endpoint	Description
Create Capture	POST /captures	Store metadata (device_id, build_id, scene_key)
Upload Image	POST /captures/{id}/file	Save file → compute metrics
Get Metrics Trend	GET /metrics/trend?device_id=&scenario=&metric=	Return avg value per build
Get Regressions	GET /regressions?device_id=&scene_key=&metric=&baseline_build=&current_build=	Return Δ and flag if > 5% drop
List Captures	GET /captures?device_id=&build_id=	Return latest captures for grid view

Metric formulas

Sharpness ≈ variance of Laplacian (gray image)

Contrast ≈ pixel standard deviation

Exposure ≈ mean brightness / 255

Frontend ( React + Tailwind )
Page	Key Components	Purpose
Dashboard	MetricLineChart (Chart.js)	View trends over builds
Regressions	RegressionTable + badges	See Δ and flagged scenes
Compare	CompareScrubber (A/B slider)	Visual check of scene
Upload	Drag-and-drop → API calls	Add new captures (Stretch)
🧮 6. Data Model (Postgres)
Table	Key Columns
Device	id, name
Build	id, label, commit_sha
Shoot	id, title, scenario
Capture	id, device_id, build_id, shoot_id, scene_key, image_path
Metric	id, capture_id, metric, value
Baseline	id, device_id, scene_key, metric, value, build_id
🧠 7. Regression Logic
delta = current_value - baseline_value
if (metric in ["sharpness","contrast"]):
    regressed = delta / baseline_value < -0.05
elif (metric == "exposure"):
    regressed = delta < -0.05


Display ↓ Regressed if true; otherwise “OK”.
